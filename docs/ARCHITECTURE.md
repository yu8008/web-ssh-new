# 架构说明（社区版）

> English version: [ARCHITECTURE.en.md](./ARCHITECTURE.en.md)

## 1. 总体架构

WebSSH Gateway 采用前后端分离架构，后端负责鉴权、SSH 会话和业务 API，前端负责会话交互、可视化和文件操作。

```mermaid
flowchart LR
    U[浏览器用户] --> F[Frontend React + xterm]
    F -->|HTTP| B[Backend FastAPI]
    F -->|WebSocket| B
    B --> DB[(SQLite)]
    B --> S[(目标 SSH 主机)]
    B --> K[session-transfer-files/tmux]
```

## 2. 后端模块拆分

- `app/main.py`：应用启动、路由注册、静态资源挂载、会话状态初始化。
- `app/api/`：REST + WebSocket 接口层。
- `app/services/`：鉴权、加密、SSH 会话管理、会话状态广播等核心业务。
- `app/models/`：SQLAlchemy 模型（用户、连接、会话）。
- `app/core/`：配置、数据库、日志、应用状态装配。

### 2.1 接口分层

- `auth.py`：登录、改密。
- `connections.py`：连接管理（增删改查）。
- `sessions.py`：会话创建、查询、重试、断开、备注、终端 WebSocket。
- `ws_sessions.py`：会话状态广播 WebSocket。
- `system.py`：系统监控 + 文件管理能力。
- `health.py`：健康检查。

## 3. 前端模块拆分

- `src/pages/Login.tsx`：登录页。
- `src/pages/Sessions.tsx`：连接与会话管理页。
- `src/pages/Terminal.tsx`：终端页（xterm + 文件侧栏 + 系统监控）。
- `src/components/FileBrowser.tsx`：远程文件操作 UI。
- `src/components/SystemMonitor.tsx`：监控面板。
- `src/lib/api.ts`：统一 API 封装、错误处理、鉴权头处理。
- `src/context/AppContext.tsx`：主题与网络状态上下文。

## 4. 核心数据流

### 4.1 登录与鉴权

1. 前端调用 `/auth/login`。
2. 后端校验用户名密码、失败次数与锁定状态。
3. 返回 JWT，前端存储在 `localStorage` 或 `sessionStorage`。
4. 后续请求通过 `Authorization: Bearer <token>` 访问受保护 API。

### 4.2 终端会话

1. 前端创建会话 `/sessions`。
2. 后端解密连接凭据，建立 SSH 连接并创建 PTY。
3. 前端连接 `/sessions/ws/terminal/{session_id}`。
4. 终端输入通过 WebSocket 下发到 SSH，输出实时回传。

Ctrl/Cmd+V 与 Ctrl+Shift+V 保留浏览器的粘贴事件，不把 Ctrl+V 控制字符转发给远端读取剪贴板。文本通过 xterm 的 `paste` API 发送，保留换行规范化和远端 bracketed-paste 模式。剪贴板图片优先于同时存在的文本元数据，经带会话所有权校验的 `/system/clipboard-image/{session_id}` 上传；单张上限 20 MiB，校验 PNG/JPEG/WebP/GIF 类型及文件头。图片通过独立 SSH 连接的二进制 stdin 写入随机私有 `/tmp/webssh-clipboard.*/image.*` 文件（目录 0700、文件 0600），无需 SFTP 或 X11，再将路径逐张粘贴到终端。Codex 图片输入方式见 [OpenAI 官方文档](https://learn.chatgpt.com/docs/image-inputs?surface=cli)。

图片上传期间保留后续粘贴的顺序，阻止 Enter 提前提交；上传超时、失败或连接变化时提示重试，不向新连接注入旧图片路径。关闭终端会取消待完成上传。成功上传的图片保留在目标机器的临时目录供远端程序读取，后续清理由目标系统的临时目录策略负责。

每个终端 WebSocket 使用独立的尺寸更新队列，串行执行 SSH/tmux 尺寸命令，等待期间合并为最新尺寸，避免阻塞后续键盘与滚轮输入；连接断开时取消未完成的尺寸任务。顶部“网页”延迟来自浏览器到网关的 HTTP 健康检查，“SSH”延迟来自网关到目标的命令探测。两者均包含对应请求的处理耗时，不代表按键到画面显示的完整延迟。

任务通知使用独立的 `/notifications/ws` 应用级连接，复用 JWT 子协议鉴权；按用户隔离，离开终端进入其他页面仍可接收。SSH 实时输出通过最多保留 4096 字符的状态机观察 OSC 7501、OSC 9、受限的 OSC 777 和独立 BEL；不扫描对话正文，不按输出静默时间推测完成，不修改原始输出、序号、ACK 或回放。OSC 终止用 BEL、标题、颜色查询、进度、超链接及其他控制字符串不会成为普通响铃。Codex 的工作／阻塞状态与原生完成通知组合识别；Claude 的原生主会话 `done` 优先于 Stop Hook，忽略带任务 ID 的后台完成；没有原生状态时使用 Hook 兼容路径。提问、批准和主会话结束分别记录，中间工具完成不报整轮结束。

通知写入经过有界队列，在工作线程内持久化，避免数据库和慢通知客户端阻塞终端输出。每用户最多保留 200 条、7 天内的通知，存储事件类型、会话名称和已读时间，不保存对话正文；此期限只影响通知收件箱，不增加终端历史持久化。首次连接、重新连接和慢客户端恢复都发送静默快照；已读通过 HTTP 和通知连接在设备间同步。浏览器只为近 10 秒内的新事件考虑播放声音，用 IndexedDB 事务在同一浏览器标签页间原子领取事件；短时间集中事件优先提醒用户操作。声音开关、类别、音量和仅后台播放保存在设备本地，首次需点击启用并试听；音频权限失败和 AudioContext 暂停可见。通知弹出不抢焦点、不滚动终端、不清除选区。

远端接入仅在用户点击“接入 CLI 提醒”时执行：保留、备份并合并 Codex 的三个 TUI 通知设置及 Claude Hook，预检查所有文件后原子写入，失败回退，撤销只恢复仍由本功能管理的键及处理器，保留后续手工修改。已验证 Codex 0.163.0、Claude Code 2.1.306；低于这些版本不自动写入配置。Claude 的 `AskUserQuestion`／`ExitPlanMode`、批准请求及通知通过 `terminalSequence` 转交给 CLI 写入；迟到的批准通知复用请求 ID，不重复响。若检测到其他用户／项目 Stop Hook，禁用可能提前报完成的 Stop 回退，此时完成通知依赖原生状态；通过额外命令行设置或插件提供的自定义 Stop Hook 需单独验证。首次接入后使用新启动的 CLI 会话，接入操作不重启现有 CLI。

tmux 会过滤部分 OSC 7501。增强会话接入时配置面板专用的输出管道，只把短的状态／能力消息包装后转发，不记录或复制普通输出；保留既有管道，存在用户管道时拒绝覆盖。撤销关闭本功能管道，并在设置未被再次修改时恢复 passthrough 的原值及继承方式。原生状态握手在某些 tmux 版本中会先被本地终端探测应答结束，Claude 在这种情况下使用上述 Hook 路径，不能把未验证的自定义继续执行 Hook 视为可靠完成通知。浏览器冻结、设备休眠／锁屏、关闭网页和网关 SSH 断开期间不保证即时提示音；没有后台推送或系统桌面通知。

支持探测的新客户端每 5 秒在终端现有 WebSocket 上发送一次 `ping`，收到匹配的 `pong` 后，顶部优先显示“终端”往返延迟；原 HTTP 健康检查值保留在提示中。旧服务端不回复时继续显示“网页”HTTP 探测，不能将其等同于终端长连接延迟。探测只保留一个未完成请求，15 秒超时后清除旧值，后台标签页不采样。`pong` 使用同一个输出 writer 发送，最多保留一个待发回复，可越过排队的输出片段但不会打断正在发送的消息。该指标包括浏览器和网关调度，不包括 SSH、Codex 处理和终端解析/绘制。

终端输出由每个浏览器连接独立的有界 writer 顺序发送，实时片段让出一次事件循环以合并已就绪的 SSH 输出，不再为每次输入回显固定等待 8 ms，单批目标上限为 64 Ki 字符。历史缓冲使用 deque，保留最近 4,000 个片段，且不超过 8 MiB UTF-8 数据。

新客户端协商 `webssh.output.v1` 子协议，以 `replay_start`、带 `seq` 的 `output` 和 `replay_end` 划定历史与实时输出边界。订阅和历史快照在同一事件循环操作中完成，避免回放与实时输出交错；重连会重置终端并回放近期历史，不提供跨连接的增量续传。未协商子协议的旧客户端继续接收原始文本。

前端以 16 Ki 字符块串行交给 xterm，每轮最多处理 8 次写入或约 4 ms 后让出主线程。回放期间抑制终端自动设备/颜色/光标及 DEC 模式查询应答；真实键盘输入仍可发送。输出更新保留当前阅读位置，用户正在滚动或拖动选区时优先处理用户操作。服务端待发送队列超过 16 MiB，或前端待解析队列超过 16 Mi 字符时，会显式断开并重新回放，避免静默丢弃 ANSI 数据。

空闲输出队列收到数据后立即交给 xterm；小片段及其完成通知一起合并，空记录保留回放/重置屏障。终端内核与 WebGL/fit 插件使用配套的 xterm 6 版本，由内核处理 DEC 2026 同步重绘及缺失结束标记的超时恢复；数据继续按顺序解析并确认，不为等待完整画面阻塞 WebSocket 流控。

滚轮在手势开始时选择本地历史、应用鼠标或非鼠标翻页路径；同一手势不在本地与远端之间反复切换，空闲 120 ms 或终端模式改变后重新判断。普通滚轮位移乘以 0.85，保留像素/行/页输入比例和小数余量；应用鼠标路径每帧分批发出，未发送意图最多保留 256 次报告，反向、键盘输入、点击和失焦会取消过时意图。已经编码的输入仍保持顺序。浏览本地历史时，滚轮、鼠标移动和选择不会作为实时应用输入，也不会触发输入跟随到底部；真实键盘输入仍沿用终端的跟随策略。

TUI 选区快照复用未变文本的列偏移，保留重复行独立身份；扩展长选区时增量更新位置索引和容量统计。拖选在边缘区域渐进加速，指针到文字区域边界即可达到 240 行/秒的目标速度；在最外侧停留 400 ms 后再用 400 ms 平滑提高到 360 行/秒，离开快速区或反向会重置加速。本地拖选每帧最多推进 6 行，小窗口进一步限制为四分之一屏。TUI 拖选先用一个报告确认应用步长，再以尚未显示的移动量控制发送窗口：精细区域最多 4 行，快速区域约占正文四分之一且最多 12 行（应用自身单步更大时仅发送一步）。按 8–64 ms 的节奏逐个发送报告，完整画面实际显示后才释放对应额度；若应用合并输入导致窗口停止推进，重试会逐渐放慢本次手势的发送节奏。计时和位移额度均有上限，短暂阻塞不会积累大量补滚。

TUI 高亮使用固定的 3 个背景矩形，独立于 xterm 的输入清除选区逻辑，不复制文字；DOM 与 WebGL 共用该显示层。指针和高亮按已显示画面的行身份定位，解析中的新画面不会提前改变其坐标；完整画面渲染时同步提交高亮。反向拖选时，若固定标题或页脚与当前正文之间隔着已离屏的历史，边缘终点映射到当前正文边界。复制及右键菜单继续使用不可变文本快照。文字采集与绘制分开，移出边缘、反向、松手和失焦时停止尚未发出的旧方向报告，已发出操作的迟到画面仍可进入复制快照。

重复文本本身不再作为整帧未完成重绘的依据；分片重绘只检查新进入边缘是否仍留着旧行。收到同步重绘结束标记后，允许边缘出现合法重复行，避免长距离拖选在重复内容处停住，同时保留对半帧和无法确认位移的画面的保护。

终端历史默认保留 10,000 行，可在系统设置中选择 5,000 / 10,000 / 50,000 / 100,000 行。该偏好仅保存在当前浏览器，保存后重新打开终端生效，不改变服务端回放缓冲大小。选择与复制继续使用现有 TUI 跨屏选择逻辑，复制结果保持纯文本，不包含 ANSI 控制序列。

渲染器优先使用硬件 WebGL，将密集彩色字符合批绘制；检测到软件 WebGL、浏览器限制或图形上下文丢失时回退到 DOM。滚动直接更新终端视口，交由内核按帧合并绘制，不再额外覆盖整屏文字动画或叠加固定时长的滚动惯性。持续输出不会无限重置画面检查计时，同一单元格内移动也不会重复刷新选区。

终端主题由当前浏览器本地呈现，不要求重启 TUI。两种主题都映射 235/236 面板色。深色主题继续使用 xterm 的 4.5 对比度及原有 dim 行为；浅色主题对普通文字使用 7 的目标，将 dim 文字按 80% 不透明度与实际背景混合后，保证最终颜色至少达到 4.5，并为浅色面板上的独立选区高亮保留 4.5 的对比度。默认淡化文字在白底上显示为约 #4b5462；彩色文字按需向黑或白调整，尽量保留色相。背景无法达到目标时取可实现的最高对比度。该规则同时覆盖默认色、索引色和 RGB 色，处理单元格的反色、加粗及实际背景；非文字图形沿用内核行为。

DOM 与 WebGL 在最终文字颜色解析时共用 `terminalContrast.ts`，缓存结果以复用计算；输出和历史中的 dim 等 ANSI 属性保持原样。Vite 在开发启动与生产构建时，从固定版本的 xterm 6.0.0 / WebGL 0.19.0 源码生成包含补丁的内存模块，不修改 node_modules 或提交生成的依赖包。补丁校验版本、替换位置和涉及的源码数量，依赖发生不兼容变化时构建失败。主题或对比度变化会清空普通、dim 两类颜色缓存；选区颜色也参与 WebGL 图集配置比较，确保切换后重绘已有内容。

解析前的流式颜色适配器把近黑/近白且通道差不超过 24 的中性背景转换到两个面板色号（深色通道不超过 72，浅色通道不低于 224），兼容 Codex 深浅色启动时的索引色及固定 RGB 背景。前景色、饱和彩色背景、中间灰度、文字和 OSC/DCS/APC 载荷保持原有语义。适配器最多暂存 512 字符的未完成 CSI；回放重置屏障同时清空其状态，服务端历史及协议确认仍使用原始数据。主题切换复用终端、历史、视口和选区，仅重绘可视区域；DEC 2026 期间保留最后一次主题请求，在完整画面或内核超时恢复时提交。向 tmux 上报默认颜色继续兼容后续取色，但即时显示不依赖应用重新查询颜色。

### 4.3 增强会话持久化

增强模式依赖 `session-transfer-files/tmux` 下的保活二进制与远端 `tmux`。

- 会话断开后会进入 `disconnected` 状态。
- 后台 worker 基于重试间隔策略自动尝试恢复。
- 恢复成功后状态回推给前端。

## 5. 存储模型

- `users`：用户、密码哈希、锁定状态、最后登录时间。
- `connections`：SSH 连接信息、凭据密文、远端平台信息。
- `sessions`：会话状态、PTY 信息、增强模式参数、重试计数等。

## 6. 安全设计

- 凭据加密：连接凭据使用 AES-GCM 加密后持久化。
- 密码策略：要求复杂度并支持首次登录强制改密。
- 登录风控：失败次数达到阈值后短时锁定。
- API 鉴权：JWT + issuer 校验。
- 日志追踪：请求级 request-id，便于审计与定位。
